# 12.1 AKS Troubleshooting Guide

> **Document Purpose**
>
> This document captures all major issues encountered during the
> deployment of AKS enabled by Azure Arc on Azure Local, the
> investigation process, root cause, resolution, and lessons learned.

------------------------------------------------------------------------

# 1. Scope

This troubleshooting guide covers:

-   Azure Local validation
-   Azure Arc connectivity
-   AKS deployment
-   Kubernetes access
-   Arc Networking (MetalLB)
-   Load Balancer
-   Sample application
-   Azure Monitor
-   Evidence validation

Azure Local platform healthy.

## Resolution

Continue AKS troubleshooting.

------------------------------------------------------------------------

# TS-02 Kubernetes API Timeout

## Symptom

kubectl returned:

    dial tcp ...6443 : i/o timeout

## Root Cause

Cloud Shell could not directly reach the Azure Local logical network.

## Resolution

Validated cluster from Azure Local infrastructure instead of relying on
Cloud Shell direct connectivity.

------------------------------------------------------------------------

# TS-03 ConnectedK8s Proxy

## Symptom

Proxy authentication failed.

## Root Cause

Cloud Shell managed identity limitation.

## Resolution

Identified as environment limitation.

No platform issue.

------------------------------------------------------------------------

# TS-04 MetalLB Extension

## Symptom

Portal installation failed.

## Root Cause

Portal deployment could not complete Arc Networking installation.

## Resolution

Installed successfully using Azure CLI.

Verification:

-   Arc Networking Extension
-   Provisioning State = Succeeded

# TS-05 LoadBalancer Pending

## Symptom

Service remained in Pending state.

## Root Cause

No MetalLB address pool configured.

## Resolution

Created LoadBalancer pool.

Address Range

192.168.200.240-192.168.200.249

Advertisement Mode

ARP

Result

External IP assigned successfully.

# 3. Lessons Learned

-   Always validate Azure Local before troubleshooting AKS.
-   Portal deployment is useful for learning.
-   CLI is preferred for Arc Networking configuration in this lab.
-   Validate networking before troubleshooting Kubernetes.
-   Keep monitoring validation separate from workload validation.

------------------------------------------------------------------------

# 4. Recommended Troubleshooting Sequence

1.  Validate Azure Local health.
2.  Validate Arc connection.
3.  Validate AKS resource state.
4.  Validate node pool.
5.  Validate Kubernetes workloads.
6.  Validate services.
7.  Configure MetalLB.
8.  Validate application access.
9.  Validate monitoring.
10. Collect evidence.
