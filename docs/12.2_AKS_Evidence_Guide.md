# 12.2 AKS Evidence Guide

> **Purpose**
>
> This document defines the evidence collection standard for the AKS
> enabled by Azure Arc implementation on Azure Local. It ensures every
> technical claim is backed by verifiable evidence suitable for
> accreditation, internal reviews, and future knowledge transfer.

------------------------------------------------------------------------

# 1. Evidence Principles

-   Capture evidence immediately after successful validation.
-   Use Azure Portal screenshots wherever possible.
-   Sanitize subscription IDs, tenant IDs, correlation IDs, and user
    details.
-   Keep evidence aligned with the implementation chronology.
-   Never use failed screenshots as implementation evidence.

# 5. CLI Evidence

Retain the following outputs:

-   MetalLB enable
-   LoadBalancer creation
-   Address pool creation
-   Kubernetes credential retrieval
-   Azure Local validation commands

Do not publish raw outputs containing subscription IDs or tenant
information.

------------------------------------------------------------------------

# 6. Monitoring Evidence

Capture:

-   Extension status
-   Log Analytics queries executed
-   Findings

Observation:

Azure Monitor Containers extension deployed successfully.

Container Insights telemetry was not observed during the validation
window.

------------------------------------------------------------------------

# 7. Presentation Evidence

Mandatory:

-   AKS Overview
-   Node Pool
-   Workload
-   LoadBalancer
-   NGINX Browser Validation

Optional:

-   Azure Local Health
-   Extensions

Avoid:

-   Cloud Shell errors
-   Raw CLI dumps
-   Blank monitoring charts
-   Correlation IDs
-   Subscription identifiers

------------------------------------------------------------------------

# 8. Accreditation Checklist

-   AKS deployed
-   Arc connected
-   Node pool healthy
-   Workload running
-   LoadBalancer operational
-   Application validated
-   Azure Local remained healthy
-   Evidence sanitized
-   Documentation completed
